# E5-F5-S5 Add default Secondary, Tertiary, and Error roles

## User Story

As a designer, I want Secondary, Tertiary, and Error roles to be available by default so that the palette starts with the standard Material color roles instead of requiring me to create them manually.

## Related Epic

- [E5](./E5.md) - Dynamic tonal color roles epic.

## Related Feature

- [E5-F5](./E5-F5.md) - Role toolbar ergonomics and default Material roles feature.

## Scope

- Add built-in role definitions for Secondary, Tertiary, and Error.
- Choose realistic default base colors for each new built-in role.
- Treat these roles as protected built-ins unless product rules later allow deletion.
- Update persistence defaults, migrations, import normalization, and URL sharing to include the new roles.
- Preserve compatibility for older saved states that only include Surface and Primary.

## Acceptance Criteria

- A fresh app state includes Surface, Primary, Secondary, Tertiary, and Error roles.
- Existing imported or shared states are migrated to include missing default roles without losing custom roles.
- Secondary, Tertiary, and Error roles have independent tonal state and preview settings.
- Built-in role metadata distinguishes the new roles from custom user roles.
- Store tests cover defaults, migration, serialization, and import behavior for the new roles.
