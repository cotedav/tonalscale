# E5-F5-S6 Showcase secondary, tertiary, and error Material roles in the preview

## User Story

As a designer, I want realistic secondary, tertiary, and error examples in the app preview so that I can judge how those Material roles behave in production-like interface states.

## Related Epic

- [E5](./E5.md) - Dynamic tonal color roles epic.

## Related Feature

- [E5-F5](./E5-F5.md) - Role toolbar ergonomics and default Material roles feature.

## Scope

- Add believable secondary and tertiary action examples to the existing app preview.
- Add validation labels and an alert example that use the Error role.
- Use Material role mappings for role color, on-role color, container color, and on-container color where applicable.
- Keep the main app shell driven by the Surface role.
- Preserve existing Primary examples and custom role showcase behavior.
- Ensure hover metadata identifies secondary, tertiary, and error roles and tone numbers.

## Acceptance Criteria

- The preview includes at least one realistic Secondary action button.
- The preview includes at least one realistic Tertiary action button.
- The preview includes at least one validation label and one alert using Error role colors.
- Secondary, Tertiary, and Error examples use their own generated tonal strips, not Surface or Primary colors.
- Hovering each new action exposes the correct role label and tone metadata.
- Hovering validation and alert examples exposes the correct Error role label and tone metadata.
- Component tests cover the new preview examples and role-specific hover cards.
