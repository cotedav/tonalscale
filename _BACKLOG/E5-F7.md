# E5-F7 Palette workflow, persistence, and preview fidelity feature

## Feature Statement

As a designer, I want palette sharing, role experimentation, exports, and preview rendering to reflect the same role data consistently so that I can evaluate and hand off a Material palette with confidence.

## Related Epic

- [E5](./E5.md) - Dynamic tonal color roles epic.

## Dependency Order

1. [E5-F7-S1](./E5-F7-S1.md) first replaces oversized URL state with local storage so downstream exports and share metadata no longer depend on encoded hash payloads.
2. [E5-F7-S2](./E5-F7-S2.md) then fixes SVG export to use the same customized surface values shown in the UI.
3. [E5-F7-S3](./E5-F7-S3.md) adds role swapping for direct role-purpose experiments.
4. [E5-F7-S4](./E5-F7-S4.md) adds one-way configuration copying for palette iteration.
5. [E5-F7-S5](./E5-F7-S5.md) audits preview elements against their underlying surfaces after role and surface data flow is reliable.

## Deliverables

- [E5-F7-S1](./E5-F7-S1.md): Store share state locally instead of in base64 URLs.
- [E5-F7-S2](./E5-F7-S2.md): Export customized surface role values in SVG.
- [E5-F7-S3](./E5-F7-S3.md): Swap two color role configurations.
- [E5-F7-S4](./E5-F7-S4.md): Apply one role configuration to another role.
- [E5-F7-S5](./E5-F7-S5.md): Map every preview element to the correct Material role.
