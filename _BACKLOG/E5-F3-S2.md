# E5-F3-S2 Migrate existing multi-role payloads to the dynamic schema

## User Story

As a designer, I want existing surface and primary links or imports to keep working so that prior shared palettes are not lost.

## Related Epic

- [E5](./E5.md) - Dynamic tonal color roles epic.

## Related Feature

- [E5-F3](./E5-F3.md) - Dynamic role persistence and sharing feature.

## Scope

- Migrate current version 2 payloads into the new dynamic role schema.
- Continue supporting legacy single-color payloads by initializing surface and default built-in roles.
- Map current preview fields into per-role preview settings.
- Preserve active role when it is valid and fall back safely when it is not.
- Keep malformed or unsupported payloads rejected with existing user feedback patterns.

## Acceptance Criteria

- Current version 2 surface/primary payloads import into the dynamic schema without data loss.
- Legacy single-color payloads still initialize the surface role.
- Current share URLs continue to restore the same visual result after migration.
- Unsupported future versions are rejected safely.
- Unit tests cover v2 migration, legacy migration, invalid payloads, and active-role fallback.
