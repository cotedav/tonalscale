# E5-F3-S1 Define a versioned dynamic role persistence schema

## User Story

As a designer, I want all built-in and custom role data saved in a versioned schema so that palettes can be restored reliably over time.

## Related Epic

- [E5](./E5.md) - Dynamic tonal color roles epic.

## Related Feature

- [E5-F3](./E5-F3.md) - Dynamic role persistence and sharing feature.

## Scope

- Define the next persistence version for dynamic roles.
- Persist role metadata, role order, role tonal state, per-role preview settings, active role, and global preview settings.
- Keep payloads compact enough for compressed URL sharing.
- Validate incoming payloads before applying them to the store.
- Document the schema in the story or a linked implementation note.

## Acceptance Criteria

- Exported state contains every role and enough metadata to reconstruct the palette UI.
- Role order, active role, custom labels, tonal state, and preview settings round-trip through serialization.
- Invalid role records are rejected or safely defaulted without corrupting the store.
- The schema is covered by unit tests for serialization and validation.
- The schema remains compatible with URL compression utilities.
