# E5-F7-S5 Map every preview element to the correct Material role

## User Story

As a designer, I want every preview label, icon, outline, and text element to use the correct on-color or outline role for its underlying surface so that the preview faithfully represents Material color usage.

## Related Epic

- [E5](./E5.md) - Dynamic tonal color roles epic.

## Related Feature

- [E5-F7](./E5-F7.md) - Palette workflow, persistence, and preview fidelity feature.

## Depends On

- [E5-F4-S2](./E5-F4-S2.md) - Showcase additional roles in the app preview.
- [E5-F6-S4](./E5-F6-S4.md) - Customize selected surface card tones with the mouse wheel.

## Scope

- Audit every visible app preview element that renders text, labels, icons, borders, dividers, focus states, selected rows, buttons, chips, cards, and validation states.
- Map each element to the correct Material role based on its immediate underlying surface.
- Use on-surface roles over the base surface, on-surface-container roles over surface containers, inverse-on-surface over inverse surfaces, and the matching accent/error on-colors over accent/error surfaces.
- Ensure outline and outline-variant usage matches the element's visual emphasis and underlying surface.
- Keep hover tooltip role cards consistent with the exact role used by the hovered element.
- Add tests or structured fixtures that make unmapped preview elements visible during future changes.

## Acceptance Criteria

- Every preview element with text or an icon uses a named role rather than an ad hoc color.
- Elements on surface containers use on-surface-container or on-surface-container-variant as appropriate.
- Elements on inverse surfaces use inverse-on-surface.
- Accent, secondary, tertiary, and error examples use their matching on-role colors.
- Hovering preview elements shows a role card whose name and tone match the actual applied role.
- Tests cover representative shell, table, side panel, action, validation, and role showcase elements.
