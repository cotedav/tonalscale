# E5-F7-S1 Store share state locally instead of in base64 URLs

## User Story

As a designer, I want the app to preserve my current palette without embedding the full encoded state in the URL so that shared and exported links stay short, readable, and resilient.

## Related Epic

- [E5](./E5.md) - Dynamic tonal color roles epic.

## Related Feature

- [E5-F7](./E5-F7.md) - Palette workflow, persistence, and preview fidelity feature.

## Depends On

- [E5-F3-S3](./E5-F3-S3.md) - Share dynamic roles through URL, import, and export flows.
- [E5-F6-S4](./E5-F6-S4.md) - Customize selected surface card tones with the mouse wheel.

## Scope

- Remove the base64 state string from the URL hash/query synchronization flow.
- Remove parsing, encoding, migration, and export references that only exist to support base64 URL state.
- Persist the current palette state to local storage instead.
- Keep explicit JSON import/export as the portable way to move complete palette state between devices.
- Define a migration or graceful fallback for any existing URLs that still contain legacy base64 state.
- Update SVG export footer metadata so it no longer references the removed base64 URL payload.

## Acceptance Criteria

- Changing palette settings persists across reloads through local storage.
- The app URL no longer grows with palette state changes.
- Legacy base64 URLs either import once successfully or fail with a clear recoverable state.
- SVG exports do not include base64 state links.
- Import/export JSON still round-trips all roles, preview settings, and customized surface tones.
- Tests cover local storage persistence, removed URL updates, legacy handling, and SVG metadata output.
