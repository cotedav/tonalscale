# E4-F1-S1 Model independent surface and primary tonal configurations

## User Story

As a designer, I want separate surface and primary color settings so that changing one color role does not alter the other.

## Related Epic

- [E4](./E4.md) - Multi-role tonal color system epic.

## Related Feature

- [E4-F1](./E4-F1.md) - Role-aware tonal configuration and generation feature.

## Scope

- Introduce a typed color-role identifier for at least `surface` and `primary`.
- Store a complete tonal configuration for each role, including base color, blend settings, and all generation controls.
- Track the active editing role separately from the saved configuration data.
- Initialize the surface role from the current single-color state and provide a documented default configuration for primary.
- Expose role-aware store actions and selectors without duplicating the tonal generation engine.

## Acceptance Criteria

- Surface and primary each retain an independent complete tonal configuration.
- Updating any parameter for one role leaves every parameter of the other role unchanged.
- Existing single-color application state initializes the surface configuration without data loss.
- The active role can change without resetting either configuration.
- Unit tests cover role initialization, independent updates, and role switching.
