# E5-F1-S3 Generalize role-aware tonal selectors and refresh logic

## User Story

As a developer, I want tonal scale generation and selectors to operate on any role id so that adding roles does not require new computed properties for each role.

## Related Epic

- [E5](./E5.md) - Dynamic tonal color roles epic.

## Related Feature

- [E5-F1](./E5-F1.md) - Dynamic role domain model and store architecture feature.

## Scope

- Refactor role runtime state so each role owns generated scale, metadata, and refresh scheduling.
- Replace dedicated selectors such as `surfaceExtendedStrip` and `primaryExtendedStrip` with generic role selectors.
- Keep active-role selectors for the existing editing controls.
- Ensure adding, removing, or duplicating a role correctly initializes or disposes its runtime data.
- Keep the tonal generation engine unchanged and reused by all roles.

## Acceptance Criteria

- Any valid role id can produce params, full strip, extended strip, key strip, metadata, and blend distribution.
- Adding a role generates its scale without affecting existing roles.
- Updating one role schedules only that role's refresh.
- Removing a custom role clears its runtime data and cannot leave active-role references dangling.
- Unit tests cover generic selectors, refresh isolation, and active-role fallback after removal.
