# E5 Dynamic tonal color roles epic

## Epic Statement

As a design systems practitioner, I want to define built-in and custom tonal color roles so that I can model a complete palette beyond surface and primary without the app requiring code changes for each new role.

## Goals

- Replace hardcoded surface/primary branching with a dynamic role model that supports built-in and user-created roles.
- Keep every role backed by the same tonal configuration, generated scale, surface-role mapping, and metadata pipeline.
- Let users add, rename, duplicate, reorder, and remove custom roles while protecting required built-in roles.
- Preserve dynamic roles through URLs, imports, exports, and backward-compatible migrations from the current schema.
- Keep the app preview surface-based while allowing additional roles to be showcased in believable examples.

## Deliverables

- [E5-F1](./E5-F1.md): Dynamic role domain model and store architecture.
- [E5-F2](./E5-F2.md): Role management experience.
- [E5-F3](./E5-F3.md): Dynamic role persistence and sharing.
- [E5-F4](./E5-F4.md): Dynamic role preview and export integration.
