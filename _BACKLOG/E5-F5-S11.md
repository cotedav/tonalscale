# E5-F5-S11 Replace browser alerts with an accessible dialog

## User Story

As a designer, I want destructive or blocking confirmations to use the app's dialog styling instead of browser alerts so that the experience is accessible, theme-aware, and production-ready.

## Related Epic

- [E5](./E5.md) - Dynamic tonal color roles epic.

## Related Feature

- [E5-F5](./E5-F5.md) - Role toolbar ergonomics and default Material roles feature.

## Scope

- Replace browser alert, confirm, or console-backed alert behavior in the tonal builder with an accessible app dialog.
- Use localized dialog title, body, primary action, and cancel action labels.
- Ensure the dialog supports keyboard focus management and Escape/cancel behavior.
- Remove the console alert path that causes lint warnings.
- Update tests that currently mock browser confirm or tolerate console warnings.

## Acceptance Criteria

- Role deletion, reset confirmation, or other blocking confirmations use the app dialog instead of browser alert/confirm.
- The dialog is keyboard accessible and theme-aware.
- No `console` statement remains for alert behavior in touched tonal builder code.
- `npm run lint` no longer reports the existing console warning.
- Tests cover confirm and cancel flows through the dialog.
