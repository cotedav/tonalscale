# E5-F1-S1 Introduce a dynamic color role registry

## User Story

As a designer, I want color roles to be represented as named palette entries so that the app can support roles beyond surface and primary.

## Related Epic

- [E5](./E5.md) - Dynamic tonal color roles epic.

## Related Feature

- [E5-F1](./E5-F1.md) - Dynamic role domain model and store architecture feature.

## Scope

- Replace the fixed `surface | primary` role union as the only source of truth with a dynamic role collection.
- Define role metadata including stable id, label, built-in/custom status, role kind, deletable flag, and optional capabilities.
- Keep built-in defaults for surface and primary as seeded role records.
- Preserve a separate ordered list of role ids for tab order and export order.
- Document role id rules so custom roles remain URL-safe, stable, and importable.

## Acceptance Criteria

- The store can represent an arbitrary number of roles keyed by stable ids.
- Surface and primary still initialize as built-in roles with their current default tonal settings.
- Role order is stored separately from role state and is used by consumers that render role lists.
- Custom role ids are normalized and collision-safe.
- Unit tests cover built-in role initialization, custom role metadata creation, role ordering, and id collision handling.
